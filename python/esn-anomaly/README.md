# ESN 異常検知プロトタイプ

Echo State Network (ESN / リザーバコンピューティング) を用いた単一チャネル時系列異常検知の実験実装。

## 概要

| 項目               | 内容                                                                                |
| :----------------- | :---------------------------------------------------------------------------------- |
| 目的               | 既知の動作（サイン波・ノコギリ波）を学習した ESN で、未知の波形（矩形波）を検知する |
| サンプリング周波数 | 30 Hz                                                                               |
| 信号周波数         | 2 Hz                                                                                |
| 正常入力           | サイン波、ノコギリ波、およびその切り替え                                            |
| 異常入力           | 矩形波                                                                              |

## 使い方

```bash
uv sync --extra dev        # 依存インストール
make run                   # サイン波→矩形波の基本シナリオ
make run-multi             # 5 シナリオ一括実行（T1〜T5）
make test                  # テスト（59 件）
make bench                 # 推論性能ベンチマーク
make lint && make format   # 静的解析・フォーマット
```

## アーキテクチャ

```
入力 u(t) ─→ Reservoir (units=200, sr=0.9, lr=0.3)
                 ↓ リザーバ状態 x(t)
             Ridge Readout (ridge=1e-6)
                 ↓
             予測値 ŷ(t) = u(t+1) の推定
```

学習タスクは **One-step-ahead prediction**（次ステップ予測）。
推論時の予測誤差が大きく持続するとき「異常」と判定する。

## テストシナリオ結果

| シナリオ             | 構成                                     | 判定              | 確定遅延 |
| :------------------- | :--------------------------------------- | :---------------- | :------- |
| T1 サイン波のみ      | sine × 1000                              | 検知なし ✓        | —        |
| T2 ノコギリ波のみ    | sawtooth × 1000                          | 検知なし ✓        | —        |
| T3 サイン波→矩形波   | sine × 500 → square × 500                | step 565 で確定 ✓ | 2.17 s   |
| T4 ノコギリ波→矩形波 | sawtooth × 500 → square × 500            | step 567 で確定 ✓ | 2.23 s   |
| T5 正常切り替え      | sine × 333 → sawtooth × 333 → sine × 334 | 検知なし ✓        | —        |

> **確定遅延** = 異常区間開始から `detect_persistent` が確定を返すまでの時間。
> 報告される `detection_idx` は連続超過の**開始時刻**であり、実際に確定するのは
> `detection_idx + min_duration - 1` ステップ時点。

## 考察：追従時間と安定性のトレードオフ

### 検知の 2 段構造

本実装の異常判定は 2 つのフィルタで構成される。

```
生誤差 e(t)
  ↓ [1] 移動平均（smooth_window）
平滑化誤差 s(t)
  ↓ [2] 持続判定（min_duration）
確定アラート
```

追従時間（応答速度）と安定性（誤検知しない堅牢性）はどちらのフィルタでも
**逆方向**にトレードオフする。

---

### [1] smooth_window の影響

`smooth_window` は因果的移動平均の窓幅（過去 N ステップの平均）。

**検知遅延への影響は小さい。**
矩形波への切り替え後、生誤差（raw error）が 2〜4 程度と非常に大きいため、
窓に矩形波ステップが数ステップ入っただけで平均が閾値を超える。

| smooth_window | 切替後の閾値超過開始 |  窓満杯遅延   |
| :-----------: | :------------------: | :-----------: |
|      15       |  step 505（切替+5）  | 15/30 = 0.5 s |
|      30       |  step 506（切替+6）  | 30/30 = 1.0 s |
|      50       |  step 506（切替+6）  | 50/30 ≈ 1.7 s |

**安定性への影響は大きい。**
正常切り替え（sine → sawtooth）時の過渡誤差スパイクが窓に残る時間が延びるため、
`smooth_window` を大きくするほど正常切替の見かけ上の「連続超過長」が長くなる。

| smooth_window | T5 最大連続超過（正常切替） |
| :-----------: | :-------------------------: |
|      15       |      41 step（1.37 s）      |
|      30       |      49 step（1.63 s）      |
|      50       |      51 step（1.70 s）      |

**目安：** `smooth_window` を大きくするとノイズ耐性が上がるが、
`min_duration` の下限も引き上げられる（連鎖的に検知遅延が増える）。
本実装では `smooth_window = 30`（= 1 s）が両者のバランスが良い。

---

### [2] min_duration の影響

`min_duration` は「閾値超過が何ステップ連続すれば異常と確定するか」の下限。

**検知確定遅延は min_duration にほぼ比例する。**

|     min_duration     | 検知確定遅延（T3, win=30） |      T5 誤検知       |
| :------------------: | :------------------------: | :------------------: |
|   30 step（1.0 s）   |     35 step（1.17 s）      | あり（49 step 超過） |
|   45 step（1.5 s）   |     50 step（1.67 s）      | あり（49 step ≈ 45） |
| **60 step（2.0 s）** |   **65 step（2.17 s）**    |      **なし ✓**      |
|   90 step（3.0 s）   |     95 step（3.17 s）      |        なし ✓        |

**正常切替の最大過渡期長が `min_duration` の設計下限になる。**
`min_duration ≤ 正常切替過渡期` だと誤検知し、
`min_duration > 正常切替過渡期` であれば安定して区別できる。
本実験では正常切替の最大過渡期 ≈ 49 step のため、`min_duration = 60`（20% マージン）を採用。

---

### パラメータ設計の指針

```
1. まず smooth_window を決定（ノイズ量・反応速度のバランス）
2. 運用想定の正常切り替えパターンで max_transient（最大過渡期長）を実測
3. min_duration = ceil(max_transient × 1.2) 程度に設定
4. 許容できる検知確定遅延 ≈ (smooth_window/2 + min_duration) / fs 秒
```

| パラメータ      | 増やすと                               | 減らすと                           |
| :-------------- | :------------------------------------- | :--------------------------------- |
| `smooth_window` | ノイズ耐性↑、過渡期長↑、遅延↑          | 反応速度↑、過渡期短、ノイズ誤検知↑ |
| `min_duration`  | 安定性↑（誤検知↓）、確定遅延↑          | 検知速度↑、誤検知↑                 |
| `units`         | モデル精度↑（訓練 RMSE↓）、計算コスト↑ | 計算コスト↓、精度↓                 |

### ESN の学習特性と限界

#### 混合学習による精度低下

単一サイン波のみで学習した場合の訓練 RMSE は約 0.006 だが、
サイン波とノコギリ波の混合学習では **0.17** に増加する。
これは 2 つの異なるスペクトル構造を 1 つのリザーバで同時保持することで
各波形に対する専門化が低下するためと考えられる。

精度低下の副作用として閾値（mean + 3σ = 0.53）が高めになり、
矩形波の非常に大きな誤差（raw 2〜4）でないと超えない設定になっている。
逆に言えば、サイン波やノコギリ波の通常誤差（raw 0.02〜0.05）とは
十分に乖離しており、検知の根拠は明確に維持されている。

#### リザーバ適応遅れ（Adaptation Lag）

正常切り替え時に高誤差が発生するのは、リザーバが前の波形の動特性に
適応していた内部状態から新しい波形への適応が遅れるためである。

- ウォームアップデータと同じ波形が連続する場合（T2: ウォームアップをノコギリ波で行い即ノコギリ波予測）: 遅延なし
- 異なる波形に切り替わる場合（T5: サイン波 333 ステップ後にノコギリ波）: 適応に約 49 step（1.6 s）必要

この適応遅れは ESN の「エコー」長（リーク率 `lr` と `sr` が決める）に依存し、
`lr` を大きくすると適応は速くなるが記憶（予測精度）が落ちる。

#### スペクトル構造による区別

| 波形       | 主なスペクトル成分                         |
| :--------- | :----------------------------------------- |
| サイン波   | 2 Hz のみ（単一）                          |
| ノコギリ波 | 2 Hz + 全高調波（4, 6, 8, ... Hz）         |
| 矩形波     | 2 Hz + 奇数高調波（6, 10, 14, ... Hz）のみ |

矩形波は訓練データに含まれないスペクトル成分の組み合わせを持つため、
ESN が予測できず持続的に高誤差が続く。これが検知の根拠となっている。

### 今後の課題

| 課題                                             | 対処案                                                                                |
| :----------------------------------------------- | :------------------------------------------------------------------------------------ |
| 混合学習による RMSE 増加（0.17）                 | `units` を増やす（400〜500）か、Per-wave ESN アンサンブル                             |
| min_duration を大きくすると検知が 2 s 以上遅れる | 本番では閾値を動的に調整（訓練誤差の rolling update）                                 |
| 切り替え直後の高誤差を「適応期例外」として扱う   | スイッチ検出層を追加（波形変化率の閾値判定）                                          |
| 13 関節への拡張                                  | 多次元入力（13ch）の Reservoir → 1ch Readout、または per-joint 検知の統合             |
| Jetson への移植                                  | Phase 4 完了後にリポジトリごと持ち込み、推論時間をベンチで再計測（目安 < 33 ms/step） |
