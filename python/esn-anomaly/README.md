# ESN 異常検知プロトタイプ

Echo State Network (ESN / リザーバコンピューティング) による時系列異常検知の実験実装。
単一チャネルの波形分類から、スパイク検知、2 チャンネル同期信号の監視、
アノテーション付き学習の効果検証まで段階的に拡張した。

| 項目               | 内容                                                        |
| :----------------- | :---------------------------------------------------------- |
| サンプリング周波数 | 30 Hz                                                       |
| 信号周波数         | 2 Hz                                                        |
| モデル             | Reservoir (units=200, sr=0.9, lr=0.3) >> Ridge (ridge=1e-6) |

## Phase 7: マルチ波形対応

### アーキテクチャ

```
入力 u(t) ─→ Reservoir ─→ Ridge ─→ 予測 û(t+1)
                                      ↓
                               |u(t+1) − û(t+1)| = 残差 e(t)
                                      ↓
                         smooth(e, window=30) = s(t)
                                      ↓
                     detect_persistent(s, threshold, min_duration=60)
```

### 訓練データ設計

混合訓練: `[sine × 250, sawtooth × 250] × 4 = 2000 step`

| 波形       | スペクトル成分                      |
| :--------- | :---------------------------------- |
| サイン波   | 2 Hz のみ                           |
| ノコギリ波 | 2 Hz + 全高調波（4, 6, 8 … Hz）     |
| 矩形波     | 2 Hz + 奇数高調波（6, 10, 14 … Hz） |

矩形波は訓練データに存在しないスペクトル成分の組み合わせを持つため、
ESN が予測できず高誤差が持続する。

### テストシナリオ結果

| シナリオ             | 構成                                     | 結果              | 確定遅延 |
| :------------------- | :--------------------------------------- | :---------------- | :------- |
| T1 サイン波のみ      | sine × 1000                              | 検知なし ✓        | —        |
| T2 ノコギリ波のみ    | sawtooth × 1000                          | 検知なし ✓        | —        |
| T3 サイン波→矩形波   | sine × 500 → square × 500                | step 565 で確定 ✓ | 2.17 s   |
| T4 ノコギリ波→矩形波 | sawtooth × 500 → square × 500            | step 567 で確定 ✓ | 2.23 s   |
| T5 正常切り替え      | sine × 333 → sawtooth × 333 → sine × 334 | 検知なし ✓        | —        |

### パラメータトレードオフ

`smooth_window` と `min_duration` は追従速度と安定性を同時に決定する。

| パラメータ      | 増やすと                                    | 減らすと                           |
| :-------------- | :------------------------------------------ | :--------------------------------- |
| `smooth_window` | ノイズ耐性↑、正常切替の過渡期長↑、検知遅延↑ | 反応速度↑、過渡期短、ノイズ誤検知↑ |
| `min_duration`  | 安定性↑（誤検知↓）、確定遅延↑               | 検知速度↑、誤検知↑                 |

**設計指針:**

```
1. smooth_window を決定（ノイズ量・反応速度のバランス）
2. 正常切り替えパターンで max_transient を実測
3. min_duration = ceil(max_transient × 1.2) 程度に設定
4. 検知確定遅延 ≈ (smooth_window/2 + min_duration) / fs 秒
```

本実験では正常切替の最大過渡期 ≈ 49 step のため `min_duration = 60`（20% マージン）を採用。
確定遅延 ≈ (30/2 + 60) / 30 ≈ **2.5 s**。

> **注意:** `smooth()` は因果的移動平均（過去 N ステップのみ）を使用する。
> `np.convolve(mode="same")` は中心対称窓のため**未来情報が混入**し、検知が早まる誤動作を起こす。

## Phase 8a: スパイク単発検知

### 問題設定

0.1〜1 Hz の不定期（Poisson 分布）で発生する 1 周期（15 step）スパイクを検知する。

- 正常スパイク: sin / sawtooth（既知波形）
- 異常スパイク: square（未知波形）

### 検知手法

持続判定ではなくスパイク単位の積分 MAE で判定する。

```
1. |u(t)| > spike_threshold でスパイク区間を検出
2. 区間内の残差 e(t) の平均（区間 MAE）をスコア化
3. score > anomaly_threshold（mean + 5σ）で異常判定
```

**閾値設定:**
- `spike_threshold = max(0.3, 2.5 × noise_std)` でノイズに適応
- 異常閾値は 3σ ではなく **5σ** を採用（ノコギリ波の MAE 分散が大きく 3σ では誤検知が発生するため）

### シナリオ結果

| シナリオ                 | 結果              |
| :----------------------- | :---------------- |
| S1 sin スパイクのみ      | 誤検知なし ✓      |
| S2 sawtooth スパイクのみ | 誤検知なし ✓      |
| S3 sin/saw + square 混在 | square 全件検知 ✓ |
| S4 square のみ           | 全件検知 ✓        |

**スパイク MAE の比較:** sin ≈ 0.07、saw ≈ 0.08、**square ≈ 2.43**（約 30 倍の差）

## Phase 8b: SNR × ノイズ種類スイープ

### 設定

| 項目       | 値                                           |
| :--------- | :------------------------------------------- |
| SNR        | 4, 10, 20, 100（noise_std = 1/SNR）          |
| ノイズ種類 | gaussian / uniform / laplacian / pink（1/f） |
| シナリオ   | S1〜S4（スパイク単発、Phase 8a と同様）      |
| 判定       | 4 シナリオ中いくつパスするか（0〜4）         |

### 結果（パスシナリオ数 / 4）

|           | SNR=100 | SNR=20  | SNR=10  |  SNR=4  |
| :-------- | :-----: | :-----: | :-----: | :-----: |
| gaussian  |   4/4   |   4/4   |   3/4   |   1/4   |
| uniform   |   4/4   |   4/4   |   3/4   |   1/4   |
| laplacian |   4/4   |   4/4   |   3/4   |   1/4   |
| **pink**  | **4/4** | **4/4** | **4/4** | **3/4** |

**pink ノイズが最も検知しやすい。**
1/f スペクトルは低周波成分が支配的で、square スパイクの高調波エネルギーが
相対的に際立つことが要因と考えられる。

`S3`（sin/saw + square 混在）が低 SNR で最も失敗しやすい。
混在シナリオでは正常スパイクとの境界判定が難しくなるためである。

## Phase 9a: 2 チャンネル同期信号の異常検知

### 問題設定

```
通常: A(t) = sin(2πft),   B(t) = 0.5 × sin(2πft)  ← 同期・振幅比 0.5 がリファレンス
異常: B の位相シフト (0〜360°) または振幅変化 (0.1〜0.8)
```

異常セグメントの長さは 180〜520 step（6〜17 s）のランダム一様分布。
Poisson 間隔（rate=0.05 Hz）で発生する。

### 検知手法

```
入力 [A(t), B(t)] ─→ ESN（2ch 入出力）─→ 予測 [Â(t+1), B̂(t+1)]
                                              ↓
                              B チャンネル残差 |B(t+1) − B̂(t+1)|
                                              ↓
                              smooth + detect_persistent（min_duration=60）
```

A チャンネルは常に正常なので B の残差のみで判定する。

### シナリオ結果

| シナリオ      | 異常種別       | 結果                 |
| :------------ | :------------- | :------------------- |
| S1 正常のみ   | —              | 誤検知なし ✓         |
| S2 位相シフト | B 位相ランダム | 5/5 セグメント検知 ✓ |
| S3 振幅変化   | B 振幅ランダム | 4/4 セグメント検知 ✓ |
| S4 混合       | 位相＋振幅     | 1/1 セグメント検知 ✓ |

### パラメータスイープ結果（noise_std=0.01）

**位相スイープ（振幅固定 0.5）:**

| 位相差           | 検出率           |
| :--------------- | :--------------- |
| 5°〜330°（全域） | **1.00**（100%） |

30 Hz × 2 Hz では 1 step = 24° に相当するため、
5° の差は 1 ステップ未満でありながらも ESN の記憶が長い区間の残差蓄積で検知可能。

**振幅スイープ（位相固定 0°）:**

| 振幅比               | 検出率   |
| :------------------- | :------- |
| 0.1〜0.45, 0.55〜0.8 | **1.00** |
| **0.50**（正常値）   | **0.00** |

振幅 0.5 の近傍（≈ ±0.05 以内）でのみ検知が難しくなる。

## Phase 9b: アノテーション付き学習の効果検証

### 問題設定

訓練データに異常区間が混在する場合（異常比率 **44.3%**、50% 未満）に
どのような学習戦略が有効かを比較する。

### 4 条件

| 条件                       | 方式                                                      | アノテーション要否 |
| :------------------------- | :-------------------------------------------------------- | :----------------- |
| **A: クリーン**            | 正常データのみで学習（ベースライン）                      | 不要               |
| **B: 汚染**                | 異常込みデータをそのまま学習                              | 不要               |
| **C: マスクリードアウト**  | リザーバは全データで実行。Readout は正常区間のみで学習    | **要**             |
| **D: 3ch Annotation 入力** | 学習時 `[A, B, ann(0/1)]→[A, B]`、テスト時 `ann=0` で推論 | **要**             |

**条件 C の実装:**
```python
# 1. _esn.fit(X, y) でリザーバ初期化
# 2. _reservoir.reset() → _reservoir.run(X) で全区間の状態列を取得
# 3. _readout.fit(states[normal_mask], y[normal_mask]) で正常区間のみ学習
model.fit_masked(X_train, y_train, normal_mask)
```

### 結果比較

| 条件            | S1 正常 | S2 位相 | S3 振幅 | S4 混合 | 閾値   |
| :-------------- | :-----: | :-----: | :-----: | :-----: | :----- |
| **A: クリーン** |    ✓    |  5/5 ✓  |  2/2 ✓  |  4/4 ✓  | 0.0127 |
| **B: 汚染**     |    ✓    |  3/5 ✗  |  0/2 ✗  |  2/4 ✗  | 0.0344 |
| **C: マスクRO** |    ✓    |  5/5 ✓  |  2/2 ✓  |  4/4 ✓  | 0.1129 |
| **D: 3ch ann**  |    ✓    |  5/5 ✓  |  2/2 ✓  |  4/4 ✓  | 0.0264 |

### 考察

**条件 B（汚染）の劣化:**
モデルが「振幅 0.1〜0.35 や 0.65〜0.8 の B も正常である」と学習し、
S3（振幅異常）の検出率が **0%** に低下する。
閾値が 0.034 に上昇するが、異常時の残差も同程度に下がるため検知できない。

**条件 C（マスクリードアウト）の復元:**
リザーバは異常データを通るため内部状態が汚染されるが、
Readout の学習が正常区間のみなので **B の「あるべき値」を正確に予測**できる。
閾値が 0.113 と高くなるのは、異常区間後の過渡状態が正常区間の先頭で
Readout に引き継がれ、正常区間でも予測誤差が一時的に上昇するため。
それでも異常時の残差はさらに大きいため、性能はクリーン学習と同等に回復する。

**条件 D（3ch アノテーション入力）の効果:**
学習時 `ann=1` の期間は「異常パターンを ann=1 チャンネルと関連付け」て学習し、
テスト時に `ann=0` を与えることで「正常パターンのみを予測」するよう誘導する。
閾値は 0.026（クリーンの 2 倍程度）で検知性能も完全回復。

**実用的な推奨:**
| 状況                               | 推奨方式                  |
| :--------------------------------- | :------------------------ |
| 正常データのみ収集可能             | A（クリーン）             |
| 汚染データしかない・アノテなし     | B（汚染）: 性能劣化に注意 |
| アノテーションあり・実装シンプルに | C（マスクRO）             |
| アノテーションあり・より明示的に   | D（3ch ann）              |

## Phase 10: 6 モード Multi-Head 分類と未知モード検出

### 問題設定

{sin, saw, square} の 2 チャンネル入力の波形の組み合わせを 6 モードに分類する。
既知 6 モードにない入力（「未知モード」）を自動で検出することも目標とする。

```
モード 0: sin  × sin      モード 1: sin  × saw
モード 2: sin  × square   モード 3: saw  × saw
モード 4: saw  × square   モード 5: square × square

未知モード: A = sin、B = ノイズのみ（波形なし）
```

### Multi-Head ESN アーキテクチャ

従来の 1 ステップ先予測ではなく、リザーバ状態を **分類 Head** に接続する。

```
入力 u(t) [shape (n, 2)] ─→ Reservoir（固定ランダム重み）
                                    │
                                    ↓ 状態 x(t) [shape (n, 200)]
                              ┌─────┴──────┐
                       分類 Head           予測 Head
                    Ridge → 6 次元         Ridge → 2 次元
                    one-hot 出力           u(t+1) 予測
                         │
                    argmax → モード ID
```

**Multi-Head の意図:**

| Head   | 学習タスク                     | 用途                               |
| :----- | :----------------------------- | :--------------------------------- |
| 分類   | one-hot ラベル回帰（6 クラス） | リアルタイムモード識別             |
| 予測   | 1ステップ先予測                | 未知モード検出（残差ベース補助用） |

2 つの Head は**同じリザーバ状態を共有**し、Readout の重みのみ独立して学習する。
リザーバは固定なので、Head を後から追加・差し替えてもリザーバの再学習は不要。
これはオンライン学習でクラスを動的に追加する際の設計基盤となる。

### 訓練方法

モード間でリザーバをリセットし、各モードの**安定状態**のみで Readout を学習する。

```python
# 1. 全セグメントを連結して esn.fit() → リザーバ重みを初期化
esn.fit(X_all, dummy_Y, warmup=0)

# 2. モードごとにリセット → 先頭 WARMUP=100 step を除外して状態収集
for mode_idx, seg in zip(mode_indices, segments):
    reservoir.reset()
    states = reservoir.run(seg)       # shape (n, 200)
    all_states.append(states[WARMUP:])
    all_labels.append(np.full(n - WARMUP, mode_idx))

# 3. 収集した状態で Readout を学習
readout.fit(np.vstack(all_states), one_hot(all_labels, N_MODES))
```

WARMUP 除外の理由: リザーバはリセット直後 100 step 程度が過渡状態にあり、
同一モードでも状態空間が安定しない。この区間を除くことで各モードの
「定常状態の射影」を確実に学習できる。

### 分類実験結果（TRAIN 2000 step × 6 モード、TEST 1000 step × 6 モード）

| モード          | 精度    | 備考                         |
| :-------------- | :------ | :--------------------------- |
| sin-sin         | 99.8%   |                              |
| sin-saw         | 100.0%  |                              |
| sin-squ         | 100.0%  |                              |
| saw-saw         | 100.0%  |                              |
| saw-squ         | 100.0%  |                              |
| **squ-squ**     | **75.3%** | sin-sin と混同（詳細後述） |
| **全体精度**    | **95.9%** |                              |

**squ-squ の誤分類の原因:**
矩形波の周期は 15 step（30Hz / 2Hz）で、6次・10次高調波は 1 周期あたり
それぞれ 5 / 3 サンプルしか取れない。リザーバ（sr=0.9, lr=0.3）の
有効記憶長 ≈ 1/lr = 3 step 程度であり、高調波のパターンが十分に
リザーバ状態に蓄積されず、低周波成分（2Hz）が似る sin-sin と
混同が発生する。

### 未知モード検出の工夫

未知モードは既知モードのいずれにも属さない入力を指す。
本実験では「B チャンネルに波形がなくノイズのみ」を未知として用いた。

#### 試行した検出手法の変遷

| 手法 | 検出率<br>(noise=0.01) | 結果 | 失敗原因 |
| :--- | :---: | :--- | :--- |
| Softmax 信頼度 | 0.7% | 失敗 | Softmax 出力の和は常に 1 → 未知入力でも sin-sin に高信頼度を割り当てる |
| 予測残差（共通閾値） | 0% | 失敗 | squ-squ の残差が大きく全体閾値（0.43）が上がり未知の残差（0.22）が埋もれる |
| 予測残差（モード別閾値） | 45% | 部分的 | 未知が sin-saw（閾値 0.41）に分類されると検出漏れ |
| B-RMS 閾値 | 100% | 低ノイズのみ有効 | noise_std=0.3 では未知 B_rms（0.30）が既知の最小値（0.28）と重なり破綻 |
| **スペクトルピーク比** | **100%** | **採用** | ノイズの多寡にかかわらず「周期性の有無」を直接検査する |

#### 検出手法の詳細比較

各手法を **原理・計算量・ノイズ耐性** の観点で比較する。
測定条件: n=1000 step バッチ処理、Python/NumPy 実装、i7 相当 CPU。

| 手法 | 検出原理 | 1 ステップあたりの<br>計算量 | 必要バッファ | n=1000 step<br>処理時間 | noise=0.01<br>検出率 | noise=0.30<br>検出率 | 追加制約 |
| :--- | :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **B-RMS** | B のエネルギー量（振幅が 0 かどうか） | O(1) | 30 step<br>(1000 ms) | **16 µs** | 100% | 4% | — |
| **AutoCorr** | B の自己相関（周期 T での繰り返し） | O(1) | 45 step<br>(1500 ms) | 29 µs | 100% | 64% | — |
| **XCorr(A-B)** | A と B のクロス相関（同期性） | O(1) | 30 step<br>(1000 ms) | 44 µs | 100% | 81% | A が sin 波形であることが既知 |
| **SpectralPeak** | B の 2Hz 周波数成分の比率（周期性） | O(W log W)<br>W=60 | 60 step<br>(2000 ms) | 100 µs | 100% | **99.9%** | — |

**B-RMS が最速だが高ノイズで破綻する原因:**
B-RMS は「B チャンネルに何らかのエネルギーがあるか」だけを検査する。
ノイズ自身もエネルギーを持つため、noise_std が信号振幅（amp_b=0.5）に近づくと
未知モード（ノイズのみ）と既知モード（信号＋ノイズ）の区別が困難になる。
臨界点は概ね noise_std ≈ 0.15 付近（= amp_b/√(2+1) ≈ 0.29 の半分程度）。

**SpectralPeak が高ノイズでも機能する理由:**
FFT で 2Hz ビンのパワーを全帯域のパワーで割ることで「エネルギーが 2Hz に集中しているか」を検査する。
既知モード（sin/saw/square はすべて 2Hz 基本波を持つ）は比が大きく、
ノイズのみの未知モードは全周波数にエネルギーが均等分散するため比が小さい。
ノイズが増えると比の絶対値は下がるが、既知・未知の**相対差**は維持される。

**SpectralPeak の計算コストと遅延:**
`rfft(60)` は O(W log₂ W) ≈ 60 × 6 = 360 演算/ステップ。
100 µs/call（n=1000）は 30 Hz 予算の 0.3% に過ぎず実用上問題ない。
ただし 60 step（2 秒）のバッファが必要なため、起動直後の判定は遅延する。

#### 採用手法: B チャンネルのスペクトルピーク比

```python
from esn_anomaly.detector import spectral_peak_ratio

# 訓練データ（既知モード）からの閾値計算
# 各訓練セグメントの 2Hz パワー比を計算 → 1 パーセンタイルを閾値とする
train_ratios = [spectral_peak_ratio(seg[:, 1], FREQ, FS, window=60) for seg in train_segs]
threshold = np.percentile(np.concatenate(train_ratios), 1)   # 既知の最低水準

# テスト時
peak_ratio = spectral_peak_ratio(X_test[:, 1], FREQ, FS, window=60)
is_unknown = peak_ratio < threshold
```

> **実装ノート:** 閾値はテストと同じノイズ環境の訓練データから計算する必要がある。
> noise_std=0.01 で計算した閾値（0.575）を noise_std=0.30 環境に流用すると
> 既知モードの比も下がるため誤検知が多発する。

## アーキテクチャ詳細

```
入力 u(t)  ──────────────────────────────────→ [学習: one-step-ahead]
  shape (n, d)                                    y(t) = u(t+1)
      │
      ↓
  Reservoir（固定ランダム重み、リーク統合）
      │  x(t+1) = (1-lr)×x(t) + lr×tanh(W_res×x(t) + W_in×u(t))
      ↓
  状態 x(t)  shape (n, units)
      │
      ↓
  Ridge Readout（リッジ回帰で学習: W_out = (X^T X + λI)^{-1} X^T Y）
      │
      ↓
  予測値 û(t)  shape (n, d)
```

### ESN ハイパーパラメータ

| `units`    | 200  | リザーバニューロン数                     |
| `sr`       | 0.9  | スペクトル半径（記憶-安定性の均衡）      |
| `lr`       | 0.3  | リーク率（時定数の逆数に相当）           |
| `ridge`    | 1e-6 | リッジ正則化係数                         |
| `warmup`   | 100  | 初期過渡状態を学習から除外するステップ数 |

## 実装ノート

### `smooth()` は因果的移動平均を使う

```python
# NG: np.convolve(mode="same") は中心対称 → 未来の誤差が現在に混入
# OK: cumsum ベースの過去 N ステップのみ
cs = np.cumsum(np.insert(errors, 0, 0.0))
end_idx = np.arange(1, n + 1)
start_idx = np.maximum(0, np.arange(n) - window + 1)
return (cs[end_idx] - cs[start_idx]) / (end_idx - start_idx)
```

### ESN の 2D 入出力

`reservoirpy` の `Reservoir >> Ridge` パイプラインは多次元入出力を透過的に扱う。

```python
u = np.stack([A, B], axis=1)   # shape (n, 2)
model.fit(u[:-1], u[1:])       # 2ch 同時予測
pred = model.predict(X_test)   # shape (n, 2) が返る
e_b = np.abs(u[1:] - pred)[:, 1]  # B チャンネル残差
# ⚠ compute_residual() は .ravel() で 1D 化するため 2D 残差には直接使わない
```

### `fit_masked` — アノテーション付き Readout 学習

```python
model.fit_masked(X_train, y_train, normal_mask)
# normal_mask: shape (n,), True=正常区間
# リザーバは全データで実行（状態連続性を保つ）
# Readout は normal_mask=True の区間のみで Ridge 回帰
```

## 知見と考察

全フェーズを通じて得られた設計上の判断基準と、ESN を実問題に適用する際の注意点をまとめる。

### ESN の特性と適用限界

**リザーバの有効記憶長はハイパーパラメータで決まる**

リーク率 `lr` と スペクトル半径 `sr` が記憶長の実効値を左右する。
目安として有効記憶長 ≈ 1/lr step（lr=0.3 なら 3〜4 step）。
本実験の 30 Hz / 2 Hz 設定では 1 周期 = 15 step であり、
高調波（6 Hz = 5 step/cycle、10 Hz = 3 step/cycle）のパターンが
記憶長に収まらずリザーバに蓄積されにくい。
これが Phase 10 で squ-squ（矩形波 × 矩形波）の精度が 75.3% に留まった原因であり、
「信号周波数 × ハーモニクス数 < fs/lr」を設計条件として意識する必要がある。

**Readout は線形分類器であり、表現力の上限はリザーバ状態の線形分離可能性**

リザーバが十分に高次元の非線形変換を提供していれば Ridge が線形回帰でも高精度を達成する（カーネル近似の考え方）。
ただし入力の差異が記憶長の短さによってリザーバ状態の差異に現れない場合（squ-squ と sin-sin の混同）は、
Readout をどれだけ強化しても改善しない。リザーバのパラメータか入力特徴の前処理から見直す必要がある。

**学習後のリザーバリセットを忘れると推論精度が下がる**

`reservoir.fit()` 直後の内部状態は学習の最終ステップに依存した恣意的な値になる。
推論前に必ず `reservoir.reset()` を呼んでウォームアップデータを流す設計にすること。

---

### 異常検知の方針選択

**「正常を学習して逸脱を検知」か「物理的性質の有無を直接検査」か**

ESN を使った残差ベース検知は前者に属する。
モデルが「正常パターンを正確に予測できるか」に依存するため、
訓練データの品質（汚染の有無）が直接精度に影響する（Phase 9b の条件 B で振幅異常の検出率 0%）。

一方 B-RMS や SpectralPeak は後者に属する物理量ベースの検査であり、
「B チャンネルにエネルギーがあるか」「B チャンネルに目標周波数の成分があるか」を
モデル非依存で判定する。利用できる事前知識（信号の周波数・振幅比・チャンネル間の対称性）があれば
積極的に活用することで、ESN の予測能力に依存しない堅牢な検知が可能になる。

**未知クラス（OOD）検出に Softmax は使えない**

Softmax の出力は常に和が 1 になるため、訓練分布の外にある入力に対しても
必ずいずれかのクラスに高い確率を割り当てる（Phase 10 で検出率 0.7%）。
OOD 検出には「スコアの絶対値」ではなく「スコアのエントロピー・最大値」などの別の尺度か、
予測残差や物理量ベースの補助判定を組み合わせる必要がある。

---

### ノイズ耐性の設計

**SNR よりノイズのスペクトル特性が検知精度に影響する場合がある**

Phase 8b では同じ SNR でも pink（1/f）ノイズが gaussian より検知しやすかった。
1/f ノイズは低周波成分が支配的なため、矩形波スパイクの高周波エネルギーが相対的に際立つ。
検知すべき異常のスペクトル特性を理解してノイズ種別ごとに感度を評価することが重要である。

**検出特徴量はノイズ環境に対して「不変な量」を選ぶ**

B-RMS はノイズ振幅が上がると既知・未知モードの比の差が縮まり、noise_std ≈ 0.15 で破綻した。
SpectralPeak の「2Hz ビンのパワー比」はノイズが増えると分子・分母の両方が増えるが、
既知モードの分子は信号成分が支配的な一方、未知モードの分子はノイズのみのため比の差は維持される。
このように「絶対値」ではなく「比率・正規化された量」を特徴量にすることでノイズ環境の変化に頑健になる。

**閾値はデプロイ環境と同じノイズ条件のデータから計算する**

Phase 10 で noise_std=0.01 の訓練閾値（0.575）を noise_std=0.30 の環境に流用すると
誤検知率が 42〜99% に跳ね上がった。環境のノイズレベルが変わると既知モードの特徴量分布が
シフトするため閾値を再キャリブレーションしなければならない。
本実装では閾値を 1 パーセンタイルとして計算しているが、
この計算に使う訓練データのノイズ条件をデプロイ環境に合わせることが前提となる。

---

### アノテーションの効果と実装

**44% の汚染データでもアノテーションがあれば完全回復できる（Phase 9b）**

条件 C（マスクリードアウト）は最もシンプルな実装で効果が高い。
リザーバは全データ（異常含む）で動かして状態の連続性を保ち、
Readout の学習だけを正常区間に限定する。
リザーバ状態の汚染は避けられないが、Readout が「正常時の B 値」を学習しているため
異常時の残差が正常時より大きいという関係が保たれる。

条件 D（3ch アノテーション）はアノテーション情報を入力に明示的に加えることで
リザーバ内部でも異常区間を「別モード」として表現する。
閾値が高め（0.026 vs クリーンの 0.013）になるのは、テスト時の ann=0 と
学習時の ann=0 区間の分布がより明確に分離するためであり、誤検知リスクが下がる利点もある。

---

### リアルタイム処理の制約

**因果的処理（過去データのみ参照）を一貫して守ること**

`smooth()` に `np.convolve(mode="same")` を使うと中心対称窓になり、
現在時刻 t の平滑化値が t 以降の未来データを参照する（Phase 7 で確認）。
これはオフライン解析では問題ないが、リアルタイム・評価指標の両面で整合性を損なう。
今後 Jetson 等への移植を想定するなら、バッファ設計を含めて因果性を設計段階から担保すること。

**各手法の遅延・バッファの見積もり**

| 処理 | バッファ / 遅延 | 備考 |
| :--- | :--- | :--- |
| ESN ウォームアップ | 100 step = 3.3 s | リセット後の過渡期 |
| smooth（window=30） | 30 step = 1.0 s | 平滑化の因果遅延 |
| detect_persistent（min_duration=60） | 60 step = 2.0 s | 誤検知防止の確定遅延 |
| SpectralPeak（window=60） | 60 step = 2.0 s | FFT 窓の因果遅延 |
| 合計（予測残差 + 持続判定） | ≈ 190 step = 6.3 s | 起動後の無効区間 |

**ESN 推論の計算量**

1 ステップの推論コスト ≈ 0.64 ms（30 Hz 予算 33 ms の 2%）。
Jetson での移植余裕は十分であるが、units を 200→500 に増やすと
O(units²) の行列積が 6 倍以上に膨れるため再計測が必要。

---

### Multi-Head 設計とオンライン学習への展望

**リザーバ固定 + Readout 交換可能な設計がオンライン学習の基盤になる**

Phase 10 で示した Multi-Head 構成（分類 Head + 予測 Head の共有リザーバ）は
オンライン学習への拡張を想定した設計である。
新モードが観測されたとき Readout の重み行列に新クラス用の行を追加し、
新モードのデータだけで Ridge を再フィットすれば既存 Head に影響しない。
リザーバの再学習（O(units²) の固有値計算を含む）が不要なため、
30 Hz リアルタイム環境でも軽量に対応できる可能性がある。

**未知モード検出が「新クラス発見」のトリガーになりうる**

SpectralPeak による未知検出が継続的に発火する区間を「新モード候補」として収集し、
十分な数のサンプルが溜まったとき自動で新しい Head を追加する流れが考えられる。
ただしラベルなし新モードのクラスタリング（どのサンプルが「同じ未知モード」か）は
現在の実装では未解決であり、今後の課題として残る。
